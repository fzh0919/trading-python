## 一、迭代背景与核心问题

基于 `v5.5.1` 实盘运行反馈与容器日志，本轮聚焦 4 个高优先级工程问题：

1. **USD 钱包未随美股挂单自动冻结**：Invest 双钱包拆分目前仅读取数据库静态 `usd_reserved`（默认 `0`）；实际挂出美股 BUY 限价单后，T212 总冻结 `reserved_cash` 上升，但推导公式 `derived_reserved = reserved_cash - usd_reserved / rate` 会把全部冻结错算到 GBP 钱包，导致 USD 可用虚高、GBP 可用虚低（甚至推算为负触发误报警）。用户确认：**挂美股买单一定优先使用 USD 钱包余额**。
2. **撤单被误判为「全部成交」且重复推送**：`2026-11-18 14:49 UK` 用户撤销两笔 ISA `VWRP.L` 限价买单（`133.50` / `136.20 GBP`），却收到两条 `25/25 股 @ 137.80 GBP` 的假成交回执。根因有三：
   - `HistoricalOrderItem` 解析 `/equity/history/orders` 时丢弃了 `entry["order"]["id"]`，导致 `match_fill_history()` 放弃 `order_id` 精确匹配，退化为宽松的时间窗口模糊匹配；
   - 缺少限价物理边界校验（BUY 限价 `133.50`/`136.20` 物理上不可能在 `137.80` 成交）；
   - 同一笔成交记录未做一对一互斥消耗，被两笔撤单连续认领两次。
   - 附带：ISA 为纯 GBP 单币种账户，回执尾部仍提示 `/usd` 与 `/wallet` 双钱包校准。
3. **`/report` 字数限制偏紧导致“电报体”压缩**：当前硬上限 `2200` 字（Prompt 软目标 `1700~2000` 字），且各子字段上限偏小（`headline<=45`、`macro_and_cash<=90`、`account_diagnosis<=130` 等），导致实盘早报被迫大量使用缩略语，阅读流畅度与逻辑展开不足；同时 Telegram 单条消息安全上限为 `3800` 字符，仍有充足余量。
4. **容器运行两条 WARN 根因治理**：
   - `report_bear_rebuttal` 使用 `deepseek-flash (think=HIGH)` 时，`httpx` 读超时写死 `60s`（实际 `think=HIGH` 正常耗时约 `65~85s`），触发 `ReadTimeout` 后又被当作瞬时错误重试一次，累计卡顿 `122.5s` 才降级 Gemini；
   - `semantic_audit:report` 抓出两项告警：一是 PM 在压缩 `headline` 时把撤单与吃息拼成伪因果「Invest撤AMT吃息待命」（违反挂单本已计息红线）；二是 `build_fact_baseline()` 的 `eval_text[:1200]` 截断且缺少按账户区分的全持仓成本表，导致跨账户同名标的（如 ISA & Invest 均持 `AMZN`）在含摩擦保本线核算时易被误判「底座无该成本价」，且 `logger.warning` 被截断到 `400` 字影响排障。

## 二、分模块详细设计

### M1. Invest 双钱包：USD 挂单自动冻结联动（P0）

**涉及文件**：`src/data_providers/t212_client.py`、`src/bot/handlers.py`

1. **锚点语义明确化**：
   - 本地 `wallet_balances` 中 `USD` 记录的 `available_amount + reserved_amount` 统一视为 `usd_total`（USD 钱包总现金）。
   - 继续兼容 `/usd <可用> [挂单占用]` 与 `/wallet gbp x usd y` 语法，不破坏既有命令。
2. **自动冻结分摊逻辑（`reconcile_invest_wallets`）**：
   - 当 `invest_snap.pending_orders_supported` 为 `True` 且 `rate > 0`：
     - 遍历 `invest_snap.pending_orders`，筛选 `side == "BUY"` 且 `currency == "USD"` 的活动挂单，计算单笔美元名义冻结额：优先 `quantity * limit_price`（限价单），其次 `quantity * stop_price`，兜底 `value`。求和得 `usd_pending_buy_notional`。
     - 计算自动冻结额（三重钳位）：
       ```python
       api_reserved_usd = max(0.0, float(invest_snap.reserved_cash or 0.0)) * rate
       auto_usd_reserved = min(usd_total, usd_pending_buy_notional, api_reserved_usd)
       ```
     - 若用户手动填报的 `usd_reserved > 0` 但当前已无活动挂单（`usd_pending_buy_notional == 0` 或 `invest_snap.reserved_cash <= 0.01`），自动归零释放，避免旧挂单占用永久卡死。
     - 推导结果：
       - `usd_reserved_cash = round(auto_usd_reserved, 2)`
       - `usd_available_to_trade = round(max(0.0, usd_total - auto_usd_reserved), 2)`
       - `gbp_wallet_reserved = round(max(0.0, invest_snap.reserved_cash - auto_usd_reserved / rate), 2)`
       - `gbp_wallet_available = round(max(0.0, invest_snap.available_to_trade - usd_available_to_trade / rate), 2)`
   - 当 `pending_orders_supported` 为 `False`（例如 `/equity/orders` 返回 403/瞬时失败）时，安全退回旧逻辑（沿用本地静态 `usd_avail` / `usd_reserved`）。
3. **展示同步（`handlers.py` & `t212_client.py`）**：
   - `/wallet` 与 `_format_wallet_split_line()` 清晰展示自动推导后的 USD 可用/挂单占用与 GBP 可用/挂单占用；若 GBP 存在挂单占用一并展示 `挂单 £x`。

### M2. 挂单成交回执：防撤单误报与文案按账户区分（P0）

**涉及文件**：`src/data_providers/t212_client.py`、`src/bot/scheduler.py`

1. **保留原订单 ID（`t212_client.py`）**：
   - `HistoricalOrderItem` 新增字段 `order_id: str = ""`（默认空字符串，向后兼容全部单测与历史反序列化）。
   - 解析 `/equity/history/orders` 时填充 `order_id=str(order.get("id") or "").strip()`。
2. **三道防线匹配逻辑（`scheduler.py` `match_fill_history`）**：
   - 新增可选参数 `excluded_fill_ids: set[str] | None = None`，跳过已被本轮其他消失挂单认领过的 `fill.id`。
   - **第一道防线（`order_id` 精确匹配，零误报核心）**：
     - 若 `order_row["order_id"]` 非空，且 `recent_orders` 中存在带非空 `order_id` 的记录：
       - 仅匹配 `fill.order_id == order_row["order_id"]`（且同账户、未在 `excluded_fill_ids` 中）的记录；
       - 若无匹配，**直接返回 `None`**（判定为撤单或过期，严禁降级到模糊匹配）。
   - **第二道防线（无 `order_id` 历史桩兜底 + 限价物理边界校验）**：
     - 仅当 `recent_orders` 中该账户+标的+方向的候选记录均缺失 `order_id`（兼容旧单测或极端 API 缺字段）时，才允许走时间窗口匹配；
     - 且若原挂单存在 `limit_price > 0` 且 `fill.price > 0`，强制校验物理边界（允许 `0.5%` 极小舍入容差）：
       - `BUY` 限价单：`fill.price <= limit_price * 1.005`
       - `SELL` 限价单：`fill.price >= limit_price * 0.995`
   - **第三道防线（一对一互斥认领）**：
     - `match_fill_history()` 返回结构新增 `"fill_ids": [str, ...]`；
     - `_collect_order_fill_receipts()` 维护 `claimed_fill_ids: set[str]`，每成功匹配一笔消失挂单，立即将其 `fill_ids` 加入 `claimed_fill_ids`，确保同一笔成交绝不被重复认领。
3. **回执尾部文案按账户区分（`format_fill_receipt`）**：
   - `account.upper() == "ISA"`：`• 现金与持仓已变：请用 /pos 复核实时仓位。`
   - `Invest`（或其他多币种账户）：保留 `• 现金与持仓已变：请 /usd 金额 或 /wallet gbp x usd y 校准钱包，再用 /pos 复核实时仓位。`

### M4. DeepSeek 高峰期超时治理 & Semantic Auditor 底座增强（P1）

**涉及文件**：`src/config.py`、`config.yaml`、`src/agents/llm_client.py`、`src/main.py`、`src/agents/report_agent.py`、`src/agents/semantic_auditor.py`

1. **DeepSeek `think=HIGH` 高峰期超时与快速故障转移**：
   - 背景：`07:30 UK` 早报对应中国时间 `14:30/15:30` 高峰期，DeepSeek `think=HIGH` 正常响应常达 `70~110s`（且 `semantic_audit_report` 实测已达 `38.3s`，逼近 `40s` 侧车上限）。
   - `src/config.py` `ModelsSection`：
     - 新增 `deepseek_round_timeout_seconds: float = Field(default=150.0, ge=15.0, le=300.0)`；
     - `ds_helper_timeout_seconds` 默认值从 `40.0` 调至 **`60.0`**，校验上限从 `le=60.0` 放宽至 `le=120.0`。
   - `config.yaml` `models` 节点同步更新：
     - 新增 `deepseek_round_timeout_seconds: 150.0`；
     - 将 `ds_helper_timeout_seconds: 40.0` 改为 `ds_helper_timeout_seconds: 60.0`。
   - `src/main.py` 创建 `LLMBackend` 时显式透传 `deepseek_round_timeout_seconds=cfg.models.deepseek_round_timeout_seconds`。
   - `src/agents/llm_client.py`：
     - 将 `LLMBackend.__init__` 默认 `deepseek_round_timeout_seconds` 同步为 `150.0`，`httpx.AsyncClient` 读超时与单轮 `asyncio.wait_for` 均对齐该值；
     - 在 DeepSeek 重试循环（`_deepseek_generate_round` / `_call_deepseek_with_retry`）中，将 `httpx.TimeoutException`（含 `httpx.ReadTimeout`）与 `asyncio.TimeoutError` / `TimeoutError` 纳入 `self.timeout_max_retries`（默认 `0`）控制：真超时超过 `150s` 时立即快速切换备援模型，不再白等第二轮 `150s`（在 `report_step2_timeout_seconds=660s` 预算内安全可控）。
2. **PM Prompt 补防“撤单吃息”伪因果**：
   - 在 `src/agents/report_agent.py` PM Prompt 中补充明确约束：严禁在 `headline` 或任何理由中把「撤单」和「吃息」写成因果关系（如“撤X吃息待命”），未成交限价挂单本就计息，撤单原因只能是追高/超频/盈亏比不足等交易逻辑。
3. **Semantic Auditor 底座与日志增强（`src/agents/semantic_auditor.py`）**：
   - `build_fact_baseline()` 增加全量精简「双账户持仓成本与现价表」（逐账户列出 `ISA`/`Invest` 每只持仓的 `yahoo_symbol`、`avg_price`、`cur_price`、`inst_currency`、`return_pct`），防止 `eval_text[:1200]` 截断或跨账户同名标的（如 `AMZN`）导致质检员误判「底座无该成本价」；
   - `_emit_violations()` 中 `logger.warning` 输出完整违规原文（不再截断到 `400` 字），仅 `ops-notify` 告警推送保留 `400` 字上限。
