### 1.2 定位出的 4 处外部资金流实盘 Bug

1. **Bug 1（周六体检无视外部资金流）**：`weekly_audit_mixin.py:74-87` 直接用两个资产快照比值计算 `account_change_pct`，完全未剔除期间入金/出金。
2. **Bug 2（`/perf` 分账户 TWR 双计外部流）**：`performance.py:314` `compute_account_split_performance` 将单账户净值构造为 `"total_value_gbp": value + flow`。但 T212 的 `isa_value_gbp` / `invest_value_gbp` 本身**已包含**当日外部资金流；再 `+ flow` 导致入金当日 `(value + flow - flow) / prev_nav - 1` 根本未剔除入金（假暴涨），次日分母虚高（假暴跌 + 假最大回撤）。
3. **Bug 3（`WITHDRAW` 出金负负得正变入金）**：`t212_client/http_mixin.py:425-426` 已将 `WITHDRAW` 标准化为负数（`-abs(raw_amt)`），但 `performance.py:74`（`sign * amount`，其中 `sign=-1.0`）与 `deployment_gate/triggers.py:289`（`net -= float(tx.amount)`）均二次取负，使真实出金在生产环境被反转为正向入金（既有单测 mock 了正数导致未检出）。
4. **Bug 4（周末 / 节假日 / 22:00 后外部流漏计）**：`nav_history` 仅在工作日 `07:30`（`/report`）与 `21:40~22:00`（`nav_snapshot`）写入，而 `build_nav_row`（`performance.py:60`）只筛选 `_event_uk_date(tx) == day`。凡在周五 22:00 后、周六、周日、休市日或工作日 22:00 后发生的出入金，下一工作日落库时会被彻底漏掉并变成假收益/假亏损。

### 1.3 设计决策备忘：为何不用「实时总金额 − 总 Deposit」替代收益率

- **接口限制**：T212 `/equity/account/summary` 不提供开户至今累计净入金；`/equity/history/transactions` 受近 30 天与分页上限约束，无法稳定反推多年累计净入金。
- **数学失真**：大额新入金会直接稀释既有亏损/盈利百分比（例：£10,000 亏 5% 后再存 £10,000，简单比值从 `-5%` 失真为 `-2.5%`），无法与 `VWRP.L` 基准做苹果对苹果的 Alpha 比较，也无法切出 7 日/30 日区间与最大回撤。
- **最终口径**：百分比收益率与超额 Alpha 严格使用剔除外部流的 **TWR**（样本不足时用 **Modified Dietz** 修正迪茨法兜底）；同时在周报横幅明文展示「**近 7 天剔入金净盈亏 £ + 期间净入金 £**」，兼顾金融严谨与肉眼可核对。

## 二、线上 SQLite 既有数据影响评估与零删库自愈策略

遵循 `AGENTS.md` 铁律：**严禁删库、严禁清空表、所有写库走 `AdvisorDatabase._connect(write=True)` 单写锁**。

| 数据表 | 已有旧数据对未来的影响 | 处理策略 |
| :--- | :--- | :--- |
| `quant_health_audits` | **无长期污染**：`/stats` 仅展示最新一条，AI 诊断不聚合历史周报；下周六新体检自动覆写展示位。 | 保留不动 |
| `pick_recommendations` | **无污染**：纯标的股价后验统计，与账户出入金无关。 | 保留不动 |
| `portfolio_snapshots` | **无污染**：仅记录客观净值快照。 | 保留不动 |
| **`nav_history`** | **有长期影响**：`/perf` 连乘最近 420 天日收益并追踪全程最大回撤；凡过去存在「周末/盘后入金漏计」或「出金负负得正」的行，会持续拉偏未来 420 天的累计 TWR、最大回撤、波动率与 Alpha。 | **启用近 30 天幂等流水自愈**（仅修 3 个 `*_net_flow_gbp` 列，绝不碰净值列） |

### 近 30 天 `nav_history` 流水幂等自愈设计

1. **触发时机**：盘后 `_run_nav_snapshot_job()` 完成当日 `upsert_nav_history` 后执行（非降级实盘数据时才运行）。
2. **安全窗口判定**：
   - 仅处理满足 `row[i-1].created_at_ms >= tx_cutoff_ms + 86_400_000`（留 1 天安全余量，确保完整落在 T212 近 30 天流水拉取窗口内）且 `row[i].created_at_ms > row[i-1].created_at_ms` 的相邻行对；
   - 按账户独立校验 `acc.transactions_supported`（ISA 与 Invest 各自独立判断：若某账户接口 403/不支持或触及分页上限疑似截断，则**跳过该账户**，绝不把已有合法流覆写成 `0`）。
3. **计算与写入**：
   - 对每一对相邻行 `(prev_row, cur_row)`，汇总 `prev_row.created_at_ms < tx.date_time_ms <= cur_row.created_at_ms` 区间内的 `DEPOSIT`（`+abs`）与 `WITHDRAW`/`WITHDRAWAL`（`-abs`），USD 流按当前 `gbp_usd_rate` 折算 GBP（缺失汇率时跳过，不捏造）；
   - 仅当 `abs(new_val - old_val) >= 0.01` 时调用 `db.update_nav_history_flows(updates)` 仅更新 `net_flow_gbp`、`isa_net_flow_gbp`、`invest_net_flow_gbp` 三列，**绝不触碰 `total_value_gbp`、`cash_gbp`、`invested_gbp`、`benchmark_close`、`created_at_ms`**；
   - 无偏差则零写库，重复执行严格幂等。

## 三、不可破坏的系统红线

1. **SQLite 单写锁**：新增 `update_nav_history_flows` 必须走 `self._connect(write=True)`。
2. **降级数据不回写**：`portfolio.is_fallback=True` 时严禁写入 `nav_history` 或触发近 30 天流水校准。
3. **双币种严格隔离**：`nav_history` 与周报净值/出入金统一 `GBP` 口径；无 `gbp_usd_rate` 时绝不把 USD 原值当 GBP 混算。
4. **Telegram 纯文本与控字**：周报禁止 `#` 与 `**`，AI 诊断放宽至 `<=600` 字并确保语义收尾完整。
5. **安全红线预检**：本次改动不新增任何 `http(s)://` 出网域名、不改环境变量/凭据、不改 `base_url`/灾备链、不改风控护栏开关。

### Step 2：修复外部资金流核算、分账户 TWR 与 30 天流水自愈底座
- **改动文件**：
  - `src/data_providers/analytics/performance.py`（并同步导出至 `src/data_providers/analytics/__init__.py`）：
    1. 抽出统一外部流计算辅助函数 `_collect_external_flows_gbp(...)`：
       - `DEPOSIT` 永远 `+abs(amount)`，`WITHDRAW`/`WITHDRAWAL` 永远 `-abs(amount)`（彻底免疫正/负符号差异）；
       - 支持时间戳窗口 `(after_ms, until_ms]`（主路径，精确捕获周末、节假日与 22:00 后出入金）；无 `after_ms` 时兼容按 `uk_date` 当日过滤（保证旧单测与首日快照向后兼容）；
       - 仅纳入外部流，维持现金利息与派息留在收益分子里的既有原则。
    2. `build_nav_row(portfolio, benchmark_close=None, uk_date=None, *, prev_snapshot_ms=None, prev_uk_date=None)`：
       - 传入前序行边界（严格早于今日），确保同日 `07:30` 与 `21:40` 覆写严格幂等；
       - 返回字典补充 `created_at_ms`（优先取 `portfolio.fetched_at_ms`），保证入库时间戳与 T212 净值抓取时刻对齐。
    3. `compute_account_split_performance`（L314）：将 `"total_value_gbp": value + flow` 修复为 `"total_value_gbp": value`。
    4. 新增 `reconcile_recent_nav_flows(nav_rows, portfolio, *, history_days=30, max_pages=3, now_ms=None) -> list[dict[str, Any]]`：计算近 30 天安全窗口内需要校准的 `*_net_flow_gbp` 增量列表。
    5. 新增 `compute_window_nav_performance(nav_rows, portfolio, *, lookback_days=7, previous_snapshot=None, now_ms=None) -> dict[str, Any]`：
       - **优先路径**：截取 `nav_history` 近 `lookback_days` 日行 + 将当前实时 `portfolio`（配对最新行之后的外部流）作为尾点，调用 `compute_portfolio_performance` 得到精确 `twr_pct`、期间总净入金 `net_flow_gbp` 与剔入金净盈亏 `net_pnl_gbp`；
       - **兜底路径**（`nav_history` 不足 2 点但有 `previous_snapshot`）：汇总 `(prev_ms, now_ms]` 区间外部流 `net_flow`，用 Modified Dietz 算 `(cur_val - prev_val - net_flow) / (prev_val + 0.5 * net_flow) * 100`；
       - **权限降级保护**：若双账户均 `ok=True` 但任一活跃账户 `transactions_supported=False` 且无法依赖已验证 `nav_history`，返回 `flows_unverified=True`，阻止周报产出虚假跑赢结论。
  - `src/engine/deployment_gate/triggers.py`（L286-L289）：`DEPOSIT` 用 `abs(float(tx.amount))`，`WITHDRAW` 用 `-abs(float(tx.amount))`。
