## 背景与实跑诊断摘要

基于 `2026-11-19` 线上 `/pick` Critic（`gemini-4-neon`, `think=MEDIUM`）完整 `systemInstruction / INPUT / OUTPUT` 日志及最终 Telegram 渲染文本的逐行穿透审计，发现本环节存在 **4 处实锤逻辑硬伤**、**5 处二次深挖盲区**与 **严重上下文噪音（~10,302 input tokens 诱发 6,023 thinking tokens，输出正文仅 546 tokens，思考/输出比达 11:1）**：

### A. 线上已暴露的 4 处 P0 逻辑硬伤
1. **下游拦截后 `consistency_and_cash_note` 沦为假账**：
   - `ISF.L` 已被 `_apply_gate_channel_constraints` 拦截，但 Telegram 底部仍输出 Critic 拦截前口算的 `全额成交后余现£29,698(41.4%，ISA £18,322、Invest £11,376)`；实际 ISA 现金根本未动（仍是 `£19,890.90`），且 Critic 口算时还把原本已在挂单占用（`£8,594.70`）里的 `ISF.L £1,020` 重复扣减了一次。违反“精确现金严禁交给 LLM 口算”系统铁律。
2. **Critic 处于“信息盲审”状态，实为 Researcher 的 JSON 排版器**：
   - `critic_sys` 要求核查 ATR 地板、分析师均值偏离（>15%）、60 日相关性、5 日财报、RSI≥72、距除息 ≤3 天（甚至写着空指指令`除息数据见候选行的「除息」标注`），但 `critic_prompt` 根本未提供任何一手候选事实数据，Critic 只能 100% 盲信 Researcher 的二手转述。
3. **同一张 `LSEG.L` 票在 Telegram 上下给出两套打架的股数、金额与门槛**：
   - `区间`（Critic）写 `9520-9560 GBp 限价买 16股(约£1,530)，净R:R 2.64:1`；`校验`（Python）写 `以损定仓上限 £1,800（预算£107÷止损5.9%），动态门槛NEUTRAL≥2.0:1，≈18股`。
   - 根因：Python `_resolve_pick_rr` 与 `compute_risk_based_size_gbp` 未把英股 0.50% 不可退印花税 + 买卖价差计入止损风险分母（若真按 Python 买 18 股触发止损将实亏 £118，超风险预算 11%）；且 `sizing.py` 未接入 VIX 动态门槛、限价入场与现价入场口径割裂。
4. **交易频率与 15 天清仓冷却硬拦截存在安全漏洞**：
   - `compute_trade_behavior_stats` 把免配额（零 Quota）的核心宽基 ETF 买入也算进了 `buys_7d=5 / buys_30d=33`；
   - `_cadence_violation`（`risk_override.py:137`）将 `if behavior.get("partial"): return None` 写在最开头，导致历史仅覆盖 `24.4 天 < 30 天` 时，**连已完整覆盖的「近 7 天频率」和「15 天清仓冷却（刚清仓 0 天的 CRWD/TSLA）」都被整段短路放行**；同时 Prompt 仍在向 Critic 喊 `模式 hard`，造成严重思考内耗。

### B. 二次深挖补齐的 5 处高价值盲区
5. **碎单矛盾放行（`below_min_order` 未拦截）**：当以损定仓上限因止损较宽低于最小建仓额（Invest `£700` / ISA 个股 `£1,200`）时，目前仅在 `risk_note` 尾部追加 `低于最小建仓额，勿碎单` 却仍放出买入推荐，自相矛盾。
6. **Invest 已有活动买单标的重复推荐漏洞**：`_apply_gate_channel_constraints` 把 `pending_buy_by_acct["INVEST"]` 混进 `own_held` 判断新开仓，导致对已挂未成交买单的同票再次推荐 `BUY` 时绕过了槽位与单日限额，可能双倍叠加热力。
7. **Schema 冲突与单测兼容红线**：`critic_sys` 让核心宽基 `stop_price/target_price` 填 `null`，但 `PickActionItem` Schema 是非 nullable 的 `NUMBER`；同时全仓 5 个测试文件强耦合 `PickDecision` 类名与字段，改造必须在保持向后兼容的前提下消除 Schema 冲突与冗长描述。
8. **偏好记忆开关只关写不关读**：`config.yaml` 已设 `user_preference_memory_enabled: false`，但 `pick_agent.py` / `chat_agent.py` 读取端未检开关，导致历史过期挂单对话继续污染输入。
9. **渲染与语义质检缺口**：拦截后 `_reconcile_pick_headline` 重建标题过机械且漏中文名；空仓兜底句硬编码旧 `R:R≥2:1`；`semantic_auditor.py` 对 `/pick` 缺少入选新标的一手事实价锚点且未校余现。

## Wave 2：Schema 洁净化、确定性余现与统一风控数学真源

> **哲学归属**：所有算术（余现、摩擦净 R:R、以损定仓股数、冷却/频率裁决）100% 回归 Python 单一真源，绝不交给 LLM 口算，同时保持 100% 既有单测兼容。

### 1. `PickDecision` Schema 兼容式洁净化（消除 `null` 冲突与冗余描述）
- **改动文件**：`src/agents/schemas.py`、`src/agents/pick_agent.py`
- **实现要点**：
  1. **保持类名与内部向后兼容**：保留 `PickDecision` / `PickActionItem` 类名及字段名（保护全仓 5 个测试文件的 Mock 契约不被破坏）。
  2. **修复 `null` vs `NUMBER` 冲突**：`PickActionItem.stop_price` 与 `target_price` 类型调整为 `float | None = Field(default=None, ...)`（下游读值均已做 `float(... or 0.0)` 防护），与“核心宽基填 `null`”提示词 100% 一致。
  3. **新增可选入场限价中枢字段**：`PickActionItem` 增加 `planned_entry_price: float | None = Field(default=None, description="建议限价入场价（本地货币，按现价/市价介入留 null）")` 与 `planned_amount_gbp: float | None = Field(default=None, description="建议本笔建仓金额（GBP 整数）")`：
     - `entry_price` 保持严格定义：**当前市场现价**（入库用于 T+5/T+20 结算锚点，由 Python 用 `bundle.current_price` 校准，绝不被限价污染）；
     - `planned_entry_price`（若提供且在合理范围内，如 `<= current_price * 1.03` 且 `> stop_price`）作为 `_resolve_pick_rr` 与 `sizing` 的限价算仓基准，缺省回退现价，彻底打通 `区间` 与 `校验` 基准。
  4. **压缩 Schema 描述噪音 & 收敛 `consistency_and_cash_note` 职责**：
     - 将 `PickActionItem` / `PickDecision` 中冗长的 900 字中文描述精简至 ~400 字（不与 `critic_sys` 重复长篇规则）；
     - `consistency_and_cash_note` 改为要求 Critic 仅输出一句 **≤45 字的风控红线与门控遵循声明（严禁手算剩余现金与占比）**；
     - 下游无论 Critic 是否在 `rejected_or_frozen` / `risk_note` 误填内容，Python 在进入护栏前均先清空为 `[]` / `""`，从代码层 100% 封死模型误泄内部审查记录的通道。

### 2. Python 确定性接管“执行后精确剩余现金”计算（终结拦截后假账）
- **改动文件**：`src/agents/pick_agent.py`、`src/agents/schemas.py`
- **实现要点**：
  1. 在 `apply_risk_override_guardrail` 与 `_apply_gate_channel_constraints` 全部执行完毕后，新增确定性函数 `_build_deterministic_cash_note(final_decision, portfolio, sizing_map)`：
     - 按最终存活的 `selected_actions` 分账户统计拟新增占用金额（优先取 Python 算仓上限与 `planned_amount_gbp` 中的合规执行额；若为 `TRIM` 不扣现金；若为 `BUY/ADD` 且该标的在对应账户已有挂单，不重复扣减已占用挂单额）；
     - 精确计算执行后：`ISA 可用 £X(总现 £Y) / Invest 可用 £Z` 及 `双账户合计余现 £T(占总资产 P%)`。
  2. 将该确定性余现串与 Critic 的短风控声明（剥离任何误写的余现数字）拼接写入最终渲染，**即使中途发生任意拦截，Telegram 展示的余现账目也 100% 精确无误**。

### 3. 统一 R:R 摩擦分母、以损定仓与碎单/重复买单硬拦截
- **改动文件**：`src/engine/portfolio_rules/dual_philosophy.py`、`src/engine/portfolio_rules/models_and_friction.py`、`src/engine/portfolio_rules/sizing.py`、`src/engine/portfolio_rules/risk_override.py`、`src/agents/pick_agent.py`
- **实现要点**：
  1. **摩擦同步计入止损风险分母（方案 A）**：
     - `_resolve_pick_rr`（`dual_philosophy.py:229-230`）：`effective_risk_pct = risk_pct + friction_pct`，净 R:R 公式升级为 `round((upside_pct - friction_pct) / effective_risk_pct, 2)`，并在返回字典暴露 `effective_risk_pct`（与纯价格止损 `risk_pct` 区分，便于 `risk_note` 清晰展示）。
     - `_build_pick_size_note`（`sizing.py:193-224`）：
       - 改用 `effective_risk_pct` 传入 `compute_risk_based_size_gbp`，保证触发止损时连同英股 0.50% 印花税 + 换汇 + 价差在内的**真实总亏损严守 `≤ max(£85, 0.75% NAV)`**（以本次 `LSEG.L` 为例：预算 `£107 ÷ 6.8% ≈ £1,570 ≈ 16股`，与风控要求严丝合缝，不再虚高给到 18 股）；
       - 同步接入 Phase 1 的 `vix` 版 `resolve_invest_dynamic_rr_floor(regime, tech, strategy, vix=macro_vix)`，确保 `校验：` 行印出的门槛（如 `高波防御≥2.5:1`）与红线 100% 一致；
       - 若 Critic 填写了 `planned_amount_gbp` 且超出 `suggested_gbp * 1.05`，在 `risk_note` 中标明按以损定仓上限钳位，杜绝 `区间` 与 `校验` 矛盾。
  2. **碎单硬拦截（修补 `below_min_order` 矛盾放行）**：
     - 在 `risk_override.py` 的 Invest/ISA 个股 `hard` 护栏中，若按 `effective_risk_pct` 算出的 `suggested_gbp < min_order_gbp`（`below_min_order=True`），直接硬拦截（`BELOW_MIN_ORDER_SIZE`），不再输出“建议买 + 勿碎单”的矛盾推荐。
  3. **封堵 Invest 已有买单重复叠加热力漏洞**：
     - 在 `_apply_gate_channel_constraints`（`pick_agent.py:345`）新增校验：若 `acct == "INVEST"`、`not is_core_etf`、`act_up in {"BUY", "ADD"}` 且标的已在 `pending_buy_by_acct["INVEST"]` 中，直接拦截（`该标的在 Invest 已有未成交买入挂单，严禁重复建仓叠加热力`）。

### 4. 修复交易频率统计污染与 `partial=True` 一刀切冷却漏洞
- **改动文件**：`src/data_providers/t212_client/context_formatting.py`、`src/engine/portfolio_rules/risk_override.py`、`src/agents/pick_agent.py`
- **实现要点**：
  1. **零 Quota 豁免对齐统计口径**：`compute_trade_behavior_stats` 新增可选参数 `exempt_symbols: set[str] | None = None`（兼容既有调用方；`/pick` 与 `/report` 传入核心宽基 `etf_set` 及基准 `VWRP.L`），统计 `buys_7d` / `buys_30d` 时排除核心宽基 ETF，不再把定投宽基算成“个股超频”。
  2. **按窗口覆盖天数分级执行硬拦截**：重构 `_cadence_violation`（`risk_override.py:137-164`）：
     - 取消“只要 `partial=True` 就整段 `return None`”的一刀切短路；
     - **15 天清仓冷却**：只要 `coverage_days >= cooldown_days`（或 `recently_closed` 里明确记录了 `days_since_sell <= cooldown_days` 的近清仓记录，如 `0天` 的 `CRWD/TSLA`）**无条件生效硬拦截**；
     - **7 天频率上限**：只要 `coverage_days >= 7` 即按 `buys_7d` 生效；
     - **30 天频率上限**：仅在 `not partial`（覆盖满 30 天）时硬拦截，不足 30 天降级为提醒。
  3. **向 Critic 清晰声明当前生效状态**：`format_trade_behavior_text` 明确标注哪些约束已触发/哪些暂缓，彻底消除 Critic 的规则猜谜内耗。
