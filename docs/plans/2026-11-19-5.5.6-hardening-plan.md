## Wave 1：LLM 工具调用末轮强制收口（修复 `gemini-4-hydrogen` 末轮误判空文本降级）

### 1. 问题现象与根因
- **线上现象**：`/pick` 的 `pick_researcher`（`gemini-4-hydrogen`, `think=HIGH`, `max_tool_rounds=2`）执行到第 3 轮（`round_idx == 2 == max_tool_rounds`）时，SDK 打印 `Warning: there are non-text parts in the response: ['function_call']`，随后触发 `模型返回空文本（finish_reason=STOP, out=226, thought=11243）` 并浪费 ~70s / 59.6k 输入 Token 后降级到 `deepseek-flash`。
- **代码根因**：
  1. `src/agents/llm_client.py` 的 `_run_model_once` 在末轮（`round_idx == max_tool_rounds`）仍原样传递 `tools=configured_tools` 且未禁用函数调用，模型不知工具预算已耗尽，继续输出纯 `function_call` 响应（无正文文本），第 687 行随即读取 `response.text` 得到空串并误报为空文本故障。
  2. `src/agents/llm_client.py` 的 `_run_deepseek_once` / `_call_deepseek_single_round` 存在同源缺陷：末轮仍发送 `tool_choice="auto"`。

### 2. 具体改动清单
- **改动文件**：`src/agents/llm_client.py`、`tests/test_llm_pricing_and_usage.py`
- **实现要点**：
  1. **Gemini 末轮禁调工具（`_run_model_once`）**：
     - 判断 `has_fn_tools = any(getattr(t, "function_declarations", None) for t in configured_tools)`（严格隔离 `GoogleSearch` 联网搜索，不对其生效）。
     - 当 `has_fn_tools` 为真且 `tool_executor is None or round_idx == max_tool_rounds` 时，在 `_make_config` 中保留 `tools=configured_tools`（维持历史 `function_call`/`function_response` 对话上下文结构合法），同时显式注入：
       ```python
       kwargs["tool_config"] = types.ToolConfig(
           function_calling_config=types.FunctionCallingConfig(
               mode=types.FunctionCallingConfigMode.NONE
           )
       )
       ```
  2. **DeepSeek 末轮同步收口（`_run_deepseek_once` & `_call_deepseek_single_round`）**：
     - 当 `openai_tools` 非空且 `tool_executor is None or round_idx == max_tool_rounds` 时，保留 `body["tools"] = openai_tools`，将 `body["tool_choice"]` 设为 `"none"`（前序轮次保持 `"auto"`）。
  3. **末轮异常诊断文案对齐**：
     - 若极端情况下（例如代理忽略 `tool_config`/`tool_choice`）末轮仍返回 `fn_calls`/`tool_calls` 且无正文文本，报错明确记录 `末轮仍返回工具调用(...)且无文本`，不再误报为普通 `模型返回空文本`。
- **预算与路由约束**：不改动 `pick_agent.py` 的 `research_rounds`（维持无方向 `2` / 有方向 `3`），不改动超时/重试/灾备链。

### 3. 验收标准与单测
- `tests/test_llm_pricing_and_usage.py` 新增 3 条离线单测：
  1. Gemini 末轮自动携带 `FunctionCallingConfigMode.NONE` 且保留 `tools`，前轮不设 `tool_config`，`use_google_search=True` 不受影响。
  2. DeepSeek 末轮 `payload["tool_choice"] == "none"` 且保留 `payload["tools"]`，前轮保持 `"auto"`。
  3. 末轮若仍只返回工具调用且无文本，失败原因包含工具名与 `末轮仍返回工具调用` 精准诊断。
