## 一、 线上实跑审计总结（2026-11-20 Gemini LOG + Telegram 全链路）

基于 2026-11-20 真实线上 `/deep` 请求（`totalTokenCount=12,664`，`candidates=1,215`，`thoughts=2,539`，反推 **Prompt 输入 ≈ 8,910 tokens**，**缓存命中 0**）及同期普通单聊对话记录，锁定 **10 项实质问题**（含归档前对抗式反查补齐的 3 项隐蔽缺口）：

### A. 逻辑与数据 Bug（5 项）
1. **`【今日风控红线】` 100% 重复注入两遍**：`chat_agent.py:_has_complete_embedded_vetoes` 做严格子串比对，`guardrails` 每条末尾带中文句号 `。`，而早报正文用 `；` 拼接且去除了句号，导致匹配恒为 `False`，白白重复 ~180 tokens。
2. **单标的误标为「多标的对标」**：`_COMPARE_HINT_RE` 包含口语高频词 `还是`（匹配「还是在 1016 成交了」），且 `decide_chat_objects` 用 `len(chosen) >= 2 or _COMPARE_HINT_RE.search(text)` 判定，导致只有 `ISF.L` 1 只标的也被贴上 `多标的对标` 标签。
3. **跨周期过期 `/pick` 污染今日主上下文**：`db.get_latest_pick_radar()` 不检查时间是否晚于今日早报，把昨晚 `11-19 18:21` 推买 EOG 的旧提案塞在 `11-20` 早报（DEFEND 0 槽位、明确撤 EOG）正下方，制造新旧指令直接冲突。
4. **陈旧早报静默伪装成“今日早报” & 双次查库**：`answer_user_chat` 并发查了两次 `get_morning_context`，却未调用 `get_morning_context_with_status` 拿 `stale` 标记与 `updated_at_ms`；若某日晨报延迟或失败，模型会把昨天早报当今天红线执行。
5. **`/deep` 指令前缀未剥离 & 无空参保护 + 缺少纯文本防 Markdown 清洗**：`/deep ...` 原样进入 Prompt 并落库进 `chat_history`（发空 `/deep` 会空烧一次 Gemini Neon）；且聊天出口缺少保留换行的轻度 Markdown 清洗，DeepSeek 偶发吐出 `**` 或 `# ` 会直接裸露在 Telegram 中。

### B. 注意力分散、上下文膨胀与口径撕裂（5 项）
6. **System Instruction 过胖（~1,900 tokens）**：日常聊天直接复用 `/report` 全量 `build_investor_profile`，充斥着仅用于早报/选股生成的细则，且「利息 / 动态 R:R / 零 Quota / 不催买」在画像内部重复 2–3 遍。
7. **早报静态快照 vs 盘中实时状态打架**：07:30 早报写核心宽基 `35.6%`、`ISF.L` 挂单 1020；08:00 成交后真实核心宽基已升至 `36.4%` 且挂单消失，但 `ContextPack` 切片仍印着早报旧价 `1020.80 GBp`（未标快照时间）并与实时持仓 `1017.40 GBX` 冲突，同时夹带无关截断新闻（`Kenya to switch on... pr`）；且 `chat_agent` 漏掉 `refresh_portfolio_fx` 兜底。
8. **现金重复打印 + `/deep` 强行展开全仓 14 行明细 + 基线块与早报重合**：顶部现金行与双账户块重复；`/deep` 问单只标的时仍全量展开 14 只持仓的 4 位小数股数与汇兑拆解；`【本周期组合基线】` 重复打印早报已有敞口及无信息量的 `合并 x11` 模板句；同时把易变的 `/pick` 夹在静态前缀中间，下午跑 `/pick` 会击穿后面基线段的 DeepSeek 前缀缓存。
9. **历史对话截断丢执行预案 & 中文别名切片 Miss**：近期助手回复硬截 380 字，会把 1,100 字 `/deep` 回复末尾最重要的【后续执行预案】（具体价位/股数）整段切掉；`decide_chat_objects` 仅索引英文代码/公司名，用户问「英伟达/微软/亚马逊/联合健康/富时/标普」时 0-Token 切片直接 Miss。
10. **盘中大盘/指数查询工具边界过死（实盘翻车点）**：对话第 3 轮问「英欧股核心指标今天开盘跌了多少」，因 `chat_sys` 将 `search_market_news` 限定在“突发实时公告”，`inspect_ticker` 描述未说明支持 Yahoo 指数代码（`^FTSE`/`^STOXX`/`^GDAXI`/`^GSPC`），且 `get_macro_snapshot` 仅有 5 日涨跌无当日涨跌，导致 DeepSeek 只能用稀疏成交的 ETF 代理价搪塞。

5. **不重复造轮子算仓位占比**：盘中实时核心-卫星与槽位校准**严格复用** `src/engine/deployment_gate/ledgers.py` 的 `classify_pending_orders` 与 `compute_account_ledgers`，保证 `/report`、`/pick`、日常聊天三处同口径。
6. **不动风控护栏开关、出网白名单常量及任何 DB 表结构破坏性改动**。

### Wave 1：逻辑纠偏、跨周期隔离与 0-Token 盘中实时结构校准

**涉及文件**：
- `src/storage/db/portfolio_repo.py`

**具体改动**：
1. **合并早报查询、透传 `stale`，并用统一交易周期 `cycle_id` 判定 `/pick` 时效（防下午 `/us` 误杀）**：
   - 在 `portfolio_repo.py` 新增向后兼容方法 `get_morning_context_meta(cycle_date=None)` 返回 `(static_report, premarket_note, conclusion, stale, cycle_date)`，以及 `get_latest_pick_radar_with_ts()` 返回 `(created_at_uk, final_text, created_at_ms)`（原 `get_morning_context` / `get_latest_pick_radar` 签名保持 100% 兼容）。
   - **反查护栏（防下午 `/us` 覆写 `updated_at_ms` 误杀今日 `/pick`）**：严禁用 `pick_created_at_ms < morning_updated_at_ms` 判定过期（因为 14:15 `/us` 调 `append_premarket_note` 会覆写 `morning_reports.updated_at_ms`，会把上午刚跑的有效 `/pick` 误杀！）。改为将 `pick_created_at_ms` 转 UTC `datetime` 后通过 `db._cycle_id(dt)` 算 `pick_cycle_date`，仅当 `pick_cycle_date == db._cycle_id()`（属于当前 07:30 UK 周期）时注入，跨周期旧 `/pick` 一律跳过。同时兼容“当日尚无早报但刚跑 `/pick`”的单测与线上场景。
   - 若 `stale=True`，将早报标题显式标注为 `【上一周期陈旧早报（今日晨报尚未生成，仅作参考）】`。
2. **修复重复红线判定（`_has_complete_embedded_vetoes`）**：
   - 对比前对 `morning_block` 与每条 `guardrail` 做统一标点规范化（去除末尾 `。；.;` 与多余空白），避免早报 `；` 拼接导致全量重复输出。
3. **修复单标的误标「多标的对标」& 补齐中文别名索引（防泛指大盘误绑 ETF）**：
   - `_COMPARE_HINT_RE` 移除口语高频误报词 `还是`（保留 `对比|比较|哪个好|选谁|vs|VS|PK|pk`）；`decision_kind = "compare"` **仅在 `len(chosen) >= 2` 时触发**。
   - 在 `_build_symbol_alias_index` 中内置轻量高频中文别名表（仅映射明确的公司/专有名称，如 `微软→MSFT`、`英伟达→NVDA`、`亚马逊→AMZN`、`谷歌/字母表→GOOGL`、`博通→AVGO`、`联合健康→UNH`、`摩根大通→JPM`、`优步→UBER`、`特斯拉→TSLA`、`苹果→AAPL`、`台积电→TSM`、`阿斯麦→ASML.AS`、`阿斯利康→AZN.L`、`联合利华→ULVR.L`、`先锋全球/全球宽基→VWRP.L`），仅注册当前 `portfolio ∪ context_pack` 中实际存在的标的；**反查护栏：严禁把泛指大盘指数的「标普」「富时」「欧股」「纳指」硬绑定到单只 ETF**，避免问大盘指数时误触发 ETF 单标的折叠。
4. **`/deep` 前缀剥离与空参保护**：
   - 在 `answer_user_chat` 入口剥离 `/deep`（及可选 `@botname`）前导指令，得到干净的 `clean_query` 用于标的解析、Prompt 末尾展示与 `db.append_chat_turn` 落库；若 `is_deep_query` 且 `clean_query` 为空，直接返回使用提示（0 LLM 调用、不写 `chat_history`）。
5. **注入 0-Token `【盘中实时结构校准】` 与零网络 `refresh_portfolio_fx` 兜底**：
   - **反查护栏（零网络 FX + 测试桩兼容）**：仅当 `portfolio.invest.gbp_usd_rate is None` 且 `hasattr(t212, "refresh_portfolio_fx")` 时，从零网络来源（`getattr(market_data, "_macro_cache", None)` 缓存或 `context_pack` 里的宏观汇率）提取 `gbp_usd > 0` 调用 `t212.refresh_portfolio_fx(portfolio, gbp_usd)`，严禁在聊天热路径新增阻塞外网请求。
   - **反查护栏（防 `bundles=None` 将短债 ETF `IBTA.L` 误算为个股卫星！）**：`ledgers.py:_is_etf_symbol` 依赖 `bundles[sym].quote_type == "ETF"` 识别非核心宽基 ETF（如 `IBTA.L`）；若直接传 `bundles=None`，`IBTA.L` 会被误计入个股卫星（10 只变 11 只）。因此在调用 `core_etf_universe_symbols` + `classify_pending_orders` + `compute_account_ledgers` 前，必须用 `context_pack["symbols"]`（含 `identity_summary` / `bundle_summary.quote_type`）与 `portfolio` 持仓名（含 `UCITS ETF` / `ETF`）零网络构造轻量 `lite_bundles` 字典传入，并包在 `try/except` 容错内（`isa.ok` / `invest.ok` 检查），输出 1–2 行实时真相：
     `【盘中实时结构校准（HH:MM UK，若与早报数字有差异一律以本行实盘为准）】：ISA 核心宽基 36.4%（含挂单 49.6%）/ 个股卫星 10 只（29.8%，超限锁死）/ 现金 33.4%（可用 £11,414）｜Invest 在险 0 槽（保本 1 只）/ 现金 92.3%`
   - 给 `ContextPack` 标的切片标题加注 `（早报静态快照，现价与挂单状态以实盘为准）`；在 `_format_context_pack_symbol_slice` 中过滤 ETF 切片中不含标的/指数关键词的无关雅虎杂讯新闻（如 `Kenya oil rig`）。

     - 去除画像内部重复表述（把重复 2–3 遍的利息、动态 R:R 门槛、零 Quota、不催买各收束为唯一 1 句）；

   - 移除动态区顶部多余的 `build_wallet_context_text(..., compact=True)` 重复现金行（下方 `【ISA 账户】` 与 `【Invest 账户】` 的 `format_account_overview` 已完整包含现金、挂单占用、双钱包拆解与汇率，仅在顶部补标 `GBP/USD 汇率` 即可）。

   - **优化跨周期对话注入**：`prev_cycle_turns` 仅在**今日对话轮数 == 0**（刚跨 07:30 早盘首轮）时保留最近 1 条作为过渡记忆，避免上午已经聊了多轮后昨晚的过期问答（如 EOG 148 留单）还留在前缀里干扰模型；为保缓存前缀稳定，将它放在 `dynamic_tail` 的 `【今日对话记录】` 开头而非 `static_prefix`。
   - **紧凑化 `/deep` 非焦点持仓**：新增 `_format_compact_positions_table(account, target_symbols)`：
     - 普通单聊（`not is_deep_query`）维持现有异动保留 + 其余常规持仓合并为 1 行汇总；
     - `/deep` 模式下，当匹配到具体焦点标的（`confirm` / `compare`）时，焦点标的 + 权重 ≥15% 或浮亏 ≤-10% 的异动仓打印完整明细，其余常规仓打印极简 1 行（`• 代码 [占比% | 浮盈%+X.X% | 现价 CCY]`，省去公司全名、4 位股数与逐项汇兑拆解），约省 ~550–700 tokens 且不丢任何持仓全貌。
3. **重排 Prefix Cache（前缀缓存）顺序**：
   - 将全天 100% 恒定的区块压在最前面：`【今日早报及美股哨兵纪要】` → `veto_section`（去重后通常为空） → `【本周期组合基线】`；
   - 将可能随盘中事件变化的本周期 `【今日选股雷达】`（若有）与 `【今日美股开盘前哨补充】`（若有）紧贴 `static_prefix` 末尾 / `dynamic_tail` 前沿放置，避免下午执行 `/pick` 或 `/us` 时连带击穿最前面 ~2,200 tokens 的早报前缀缓存（最大化 DeepSeek Context Caching 命中率）。
4. **近期对话采用「首尾保留（Head + Tail）」防预案失忆**：
   - 改造 `_format_chat_history_compact`：
     - 最近 1 轮回复若 ≤ 550 字则全文保留；若 > 550 字（典型为 `/deep` 深度回复），保留**前 300 字（结论与核心判断）+ `\n…（中略）…\n` + 后 300 字（具体执行预案/价位/股数）**，彻底解决追问上一轮挂单参数时模型失忆的问题；
     - 更早的 1–2 轮保持 320 字精简保留，其余早期轮次保持单行摘要。
