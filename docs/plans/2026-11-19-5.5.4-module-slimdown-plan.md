## 二、架构模式与 4 条工程红线

采用 **子包门面模式（Subpackage Facade Pattern）**，并严守以下 4 条红线：

1. **零行为变更**：严禁修改任何风控阈值、Prompt 措辞、SQL 表结构、HTTP 超时/重试策略或输出文案。
2. **门面 100% 向后兼容**：各子包 `__init__.py` 重导出全部公共符号及全部跨文件/单测引用的私用符号（`_xxx`），保持原 `from ... import ...` 零改动。
3. **`mock.patch` 接缝保护**：
   - `market_data` 保留顶级 `import time`、`import yfinance as yf`，子模块一律以 `yf.Ticker(...)` / `yf.download(...)` / `time.sleep(...)` 属性形式调用（严禁 `from yfinance import Ticker`），保 26 处补丁生效。
   - `report_agent`（`get_us_market_schedule_uk`、`run_forced_market_grounding`、`is_uk_bank_holiday`）与 `scheduler`（`generate_morning_report`、`run_universe_audition`）子模块对被 patch 的协作函数走运行时门面查找，保 7 处函数绑定补丁零修改通过。
4. **粒度红线**：单子模块控制在 **300~750 行**、每包 **3~6 个子模块**；允许将 500+ 行巨型函数无损提炼为同模块私有阶段函数。
